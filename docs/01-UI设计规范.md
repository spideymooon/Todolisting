## 1. 设计原则

| 原则 | 具体表现 |
| --- | --- |
| **内容优先** | Sidebar 只做导航，克制、灰色、不抢眼；视觉主体永远是右侧的任务 |
| **打开就能记** | 主界面任何页面都有常驻捕获条，窗口一打开光标就在里面。记一条任务 = 输入 + 回车，**不需要先选日期、选列表、点新建** |
| **Kanban 是任务容器，不是数据卡片** | 三列里放的是任务卡片，绝不出现「今日任务 25 / 完成率 83%」这类统计卡（§九 明确禁止） |
| **颜色是信息，不是装饰** | 全界面一个强调色。颜色只用于：优先级、到期状态、标签、完成状态 |
| **一屏之内无滚动** | 主窗口默认 **1080 × 720**，最小 760 × 520；看板三列等宽，列内纵向滚动 |
| **状态切换不打断** | 勾选完成就地打勾 + 淡出 + 平滑移动到「今日已完成」，不弹窗 |
| **先看见再提交** | 捕获条的日期解析结果**实时显示在 chip 上**，不做静默魔法；解析失败不报错、不阻塞 |

## 3. 主框架：Sidebar + 页面路由

### 3.1 结构

```
┌────────────────────────────────────────────────────────────────────┐
│ ┌──────────────┬─────────────────────────────────────────────────┐ │
│ │  TodoList    │  看板                            [搜索] [+ 添加]│ │
│ │              │  今天 · 2026年9月17日 周四                       │ │
│ │  今天     5  │ ┌─────────────────────────────────────────────┐ │ │
│ │  看板        │ │ ＋ 记点什么…  回车存到今日          → 今天  │ │ │ ← 常驻捕获条
│ │  即将到期    │ └─────────────────────────────────────────────┘ │ │   （§3.4）
│ │  全部任务    │  ┌──────────┐ ┌──────────┐ ┌──────────┐        │ │

│ │              │  │  卡片    │ │  卡片    │ │  卡片    │        │ │
```

**Sidebar 是一级导航，看板是其中一个一级页面。** 不把看板塞进 Sidebar，也不让整个应用强制看板化。

**捕获条横跨内容区、常驻在所有任务页顶部**（设置页除外），是应用的唯一默认入口。

### 3.2 侧栏规格

- 宽度 **180px**（需求建议 168–200，取中值）
- 背景 `--bg-app`，右侧 1px `--border` 分隔
- 顶部 `TodoList` 15px/500，唯一品牌露出
- 导航项：图标（线性 1.5px stroke，16px）+ 文字，13px，高 32px，左内边距 10，圆角 `--radius-sm`
  - 未选中：`--text-secondary`，图标同色
  - 选中：`--bg-active` 背景 + `--text-primary`
  - 悬停：`--bg-hover`
- 「今天」右侧显示未完成计数（`--text-tertiary` 11px）；**有逾期任务时数字变 `--due-overdue`**
- 图标全部线性风格，不用彩色图标（§八 要求「不要大量彩色图标」）
- 底部 `设置` 用一条 1px 分隔线隔开

导航项与图标：

| 项 | 图标 | 内容 |
| --- | --- | --- |
| 今天 | 日历 | 今天的任务，单列 TodoList |
| 看板 | 四格 | 三列 Kanban（本次核心） |
| 即将到期 | 时钟 | 未来到期任务 |
| 全部任务 | 网格 | 所有未删除任务 |
| 已完成 | 对勾 | 已完成任务 |
| 设置 | 齿轮 | 设置页 |

### 3.3 右侧顶部（通用 Header）

- 左：页面标题 17px/500 + 日期副标题 12px `--text-tertiary`
- 右：搜索图标按钮 + `+ 添加任务` 文字按钮（`--accent`）
- **不堆按钮**，Widget 管理入口放在设置页，不放 Header

### 3.4 常驻捕获条 CaptureBar（v0.3 新增，P0）

> **目标：打开即可输入，回车即落到今日任务。**

```
┌─────────────────────────────────────────────────────────┐
│  ＋   记点什么…  回车存到今日              ✓已添加 →今天 │
└─────────────────────────────────────────────────────────┘
  16px  输入框 14px                                    chip
```

**位置**：Header 下方、内容区顶部，`position: sticky; top: 0`，随页面滚动常驻。今天 / 看板 / 即将到期 / 全部任务 / 已完成 **五个页面都有**；设置页不显示（避免误触，且设置页有自己的一行式输入场景）。

**为什么是全局唯一一条，而不是每页各放一个**：落点由 chip 显式表达。若每页各自解析语义（今天页→今天、待办池→无日期），用户切页面时同一句话的落点会变，是不可接受的隐式行为。

**规格：**

| 项 | 值 |
| --- | --- |
| 容器高 | 44px（内容超长自动增高，最多 3 行 / 72px） |
| 背景 / 边框 / 圆角 | `--bg-surface` / 1px `--border` / `--radius-md` |
| 阴影 | `--shadow-sm`；聚焦时边框变 `--accent`（1px，不加发光） |
| 左图标 | 16px 线性 `＋`，`--text-tertiary`，与输入文字间距 10px |
| 占位符 | `记点什么…  回车存到今日`，13px `--text-tertiary` |
| 内边距 | 左 14px / 右 10px |
| 与 Header 间距 | 12px；与下方内容间距 16px |

**打开即聚焦（本需求的核心）：**

| 时机 | 自动聚焦 |
| --- | --- |
| 应用启动 / 主窗口首次显示 | ✅ |
| 从隐藏态被快捷键唤起主窗口 | ✅ |
| 侧栏切换到任一任务页 | ✅ |
| 从任务编辑器 / 弹层关闭返回 | ❌ 焦点还给触发元素 |
| 窗口仅重新激活（用户正在别处输入） | ❌ |

- 若已有**未提交草稿**，聚焦时**不覆盖内容**，光标移到末尾。
- **副作用与解法**：自动聚焦会吞掉页面级快捷键（`C` 新建、`/` 搜索）。因此 `Esc` 必须能一键释放焦点回到页面 —— 这也正面解决了《02-需求评审与改进建议》记录的「快捷键被焦点吞掉」问题。

**提交行为：**

| 操作 | 结果 |
| --- | --- |
| `Enter` | 创建 → 清空 → **保持焦点**，可连续录入下一条 |
| `Shift + Enter` | 创建 → 打开任务编辑器（补日期 / 提醒 / 标签） |
| `Esc` | 有内容 → 清空内容；无内容 → 释放焦点 |
| `↑`（输入为空时） | 焦点跳到列表第一条任务 |
| `Tab` | 切换目标 chip（今天 ⇄ 待办池） |

**目标 chip（落点）：**

- 默认 `→ 今天`，即 `due_date = today`，等价于看板「今日待完成」列
- 点击 chip 在 `今天` / `待办池`（`due_date = null`）间切换
- 默认落点可在设置页改（「捕获条默认落点」），但**每次启动都回到用户设定的默认值**，不记忆上次临时切换
- chip 样式：`--accent-soft` 底 + `--accent` 字，11px/500，圆角 4px，内边距 2px 6px，高 20px

**即时解析（先看见，再提交）：**

输入时实时解析，结果直接反映在 chip 右侧，**绝不静默改变落点**：

| 输入 | chip 显示 | 落库结果 |
| --- | --- | --- |
| `交周报` | `→ 今天` | `due_date = today`，标题「交周报」 |
| `明天 交周报` | `→ 明天` | `due_date = 明天`，标题「交周报」 |
| `周五 复盘` | `→ 周五 9/18` | 本周五（已过则顺延下周） |
| `9-20 交房租` | `→ 9/20` | 9月20日 |
| `后天 体检 #生活` | `→ 后天 · 生活` | 后天 + 自动建标签「生活」并绑定 |
| `随便写点什么` | `→ 今天` | 解析不出日期 → 用默认落点，**不报错、不阻塞** |

支持词表（**闭集，手写解析器，不引第三方 NLP 库**）：

- 相对日期：`今天` `明天` `后天` `大后天` `N天后`
- 星期：`周一`…`周日` `下周一`…`下周日`（chip 一定显示具体日期消歧）
- 绝对日期：`9月20日` `9/20` `9-20` `2026-9-20`
- 时段：`上午` `下午` `晚上` → 写入 `due_time`
- 标签：`#工作` → 自动建标签并绑定（P1 启用 `tags` 表后生效）
- **不做**：优先级语法（`!1`）。优先级用卡片右键菜单或 `···` 改，避免输入语法过载。

**连录反馈（关键：不能吵）：**

- 每次提交，chip 右侧闪一次 `✓ 已添加`（600ms，`--due-done`），**不用 toast** —— 连记 5 条会堆 5 个 toast，这是捕获场景最典型的反模式
- 新任务在目标位置**高亮 800ms**（`--accent-soft` 底），确认落点正确
- 若当前页面不展示这条任务（如在「已完成」页记了今天的任务），chip 旁出现 `→ 去今天看看` 文字链，点击跳转。**不自动跳页** —— 打断连录比看不到确认更糟

**失败态：**

| 场景 | 表现 |
| --- | --- |
| 写库失败 | 输入内容**不清空**，chip 变 `--due-overdue` 底 + 白字 `保存失败 · 重试`，点击重试 |
| 解析歧义（如 `周三` 今天就是周三） | 按最近未来日期处理，chip 显示具体日期，不报错 |
| 输入超长 | 最多 3 行，超出内部滚动；标题入库截断 200 字 |
| 未提交草稿 + 关窗 | 草稿留在内存，下次打开仍在（不落库） |

**实现约束（架构级）：** 解析器必须是**纯函数**，放在 `src/shared/capture-parse.ts`。渲染层用它做 chip 实时预览；主进程 `task.service.createFromCapture()` 在入库前**用同一份代码重新解析一次**，并**以主进程结果为准**。渲染层只负责显示，不传递「解析后的字段」给主进程 —— 否则渲染层被篡改或版本漂移时会写进错误日期。

## 5. 看板页（本次核心，P0）

### 5.1 三列定义与数据映射

三列**不是新概念，全部映射回现有字段**，零架构改动：

| 列 | 查询条件 | 说明 |
| --- | --- | --- |
| 待办池 | `deleted_at IS NULL AND is_template=0 AND status='pending' AND (due_date IS NULL OR due_date > 今天)` | **未排入今天**的都先待在待办池 |
| 今日待完成 | `deleted_at IS NULL AND is_template=0 AND due_date IS NOT NULL AND due_date <= 今天 AND status='pending'` | 含逾期任务（浮在顶部） |
| 今日已完成 | `deleted_at IS NULL AND is_template=0 AND due_date = 今天 AND status='completed'` | |

> **v0.4 修正（实现时发现的漏洞）**：原 v0.2/v0.3 把待办池定义为 `due_date IS NULL`，这会导致**「明天到期」的任务三列都进不去，从看板上凭空消失** —— 而「明天 xxx」恰恰是捕获条最常用的一句。现改为 `due_date IS NULL OR due_date > 今天`，即「**未排入今天**的都先待在待办池」，看板因此成为所有未完成任务的完整视图。列数不变，视觉不变，只是 pool 多收一类任务。
>
> 排序：无日期的在前（收件箱），其后按 `due_date` 升序。传错误任务拖进待办池时清空 `due_date`，即「不再追踪截止」。

### 5.2 拖拽语义（§十二，全部落回现有字段）

| 拖拽 | 执行 | 附带动作 |
| --- | --- | --- |
| 待办池 → 今日待完成 | `due_date = today` | **触发提醒重算**（reminder replan） |
| 今日待完成 → 今日已完成 | `status = 'completed'`，记录 `completed_at` | **取消未发提醒** |
| 今日已完成 → 今日待完成 | `status = 'pending'`，清空 `completed_at` | **重新计算提醒** |
| 今日待完成 → 待办池 | `due_date = null` | **取消提醒**（无截止日 = 无提醒锚点） |

> 拖拽改的不是「列」，是 `due_date` / `status` 两个字段。这与提醒引擎、通知系统天然兼容，**不需要新增任何业务概念**。

**逾期任务的处理**（需求空白，补充定义）：已逾期且未完成的任务（`due_date < 今天`）自动浮到「今日待完成」列**顶部**，卡片带红色 `⚠`。若拖入待办池（清掉 `due_date`）等同于「不再追踪截止」，弹一次 toast `已移出日期追踪，可在待办池重新安排` + `撤销`。

### 5.6 列内快速添加（§十四）

**保留**，但定位收窄为「**落点明确的快捷入口**」，不再是主录入路径（主路径是 §3.4 常驻捕获条）。

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  ＋ 添加到待办池，不设定日期
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

- 默认：`--radius-md` 圆角、1px **虚线** `--border-strong`、灰字 13px、高 36px
- 点击：虚线变实线、背景变 `--bg-surface`、进入输入态
- Enter：创建任务并按列语义赋值
  - 待办池：`due_date = null`
  - 今日待完成：`due_date = today`
  - **今日已完成：不提供添加入口**（v0.3 修正）。原 v0.2 三列都有输入区，但「直接创建一条已完成的任务」没有真实使用场景，是设计冗余。该列保留空状态文案 `完成的任务会出现在这里`
  - 创建后**保持输入态并清空**，支持连续录入
- Esc / 失焦：还原为占位态
- 占位文案严格用：`添加到待办池，不设定日期` / `添加今日任务`

**三个录入入口的分工（避免重复实现）：**

| 入口 | 默认落点 | 何时用 |
| --- | --- | --- |
| **常驻捕获条**（§3.4） | 今天 | **主路径**。打开就输，落点由 chip 表达 |
| 列内快速添加（本节） | 该列语义 | 已经在盯着某一列，落点意图比输入意图更强时（尤其「待办池」） |
| 全局快速添加窗（§8） | 今天 | 应用没打开 / 被遮挡时的抓取 |

三者**共用同一个 `createFromCapture()` 与同一个解析器**，只有默认落点不同。不存在三套创建逻辑。

**显式日期优先于列语义**：在「待办池」的输入框里写 `明天 开会`，任务仍然落到明天（而不是被强行清空日期）；在「今日待完成」里写 `明天 开会`，任务会落到明天并**留在待办池列**（因为它的日期不是今天）。这是刻意的 —— 用户明确写下的日期永远压过所在列的默认语义。**列语义只是默认值，不是约束。**

### 5.7 与「今天」页的关系

「今天」页与「看板」页展示同一批任务（`due_date = today`），只是一个单列、一个三列。两者读同一份 store，`tasks:changed` 广播统一刷新 —— **不存在两套数据**（§十九）。

## 7. 桌面小组件视觉方向（参考 2.jpg）

### 7.1 总体语言

**无边框 + 半透明 + 桌面融合 + 低存在感。** 不做成普通窗口。

从 2.jpg 借鉴的视觉要素：深色玻璃质感、大圆角 16px、信息按日期分组且组头可折叠、顶部内置快速添加输入框、悬停才显示操作按钮。

### 7.2 深色玻璃 Token（小组件专用，独立于应用主题）

```css
--w-bg          rgba(24, 26, 32, 0.68);   /* 窗体底色，整体透明度由 setOpacity 统一控制 */
--w-border      rgba(255, 255, 255, 0.10);
--w-row-hover   rgba(255, 255, 255, 0.06);
--w-group-head  rgba(255, 255, 255, 0.04);
--w-text        rgba(255, 255, 255, 0.92);
--w-text-sub    rgba(255, 255, 255, 0.55);
--w-text-dim    rgba(255, 255, 255, 0.32);
--w-accent      #6EA8FE;
```

- Light Mode 用户可在组件设置里切换为浅色玻璃（`rgba(255,255,255,0.72)` + 深色文字）
- **Win10 技术边界（诚实说明）**：真正的桌面毛玻璃（Acrylic / Blur-Behind）Windows 11 才有官方 API，本项目目标环境是 Win10（19045），只能做到**均匀半透明、无背景模糊**。2.jpg 那种「透出壁纸且被模糊」的效果在 Win10 上无法等价还原，实际观感是「透出壁纸但不模糊」。若毛玻璃是硬需求需引入第三方 blur-behind 库（稳定性风险），默认**不做**。

### 7.3 「最近待办」组件（新增为默认组件形态）

即原「即将到期」组件的视觉重构，对应 2.jpg：

```
┌───────────────────────────────┐
│ 最近待办 ▾              · · · │   ← 悬停才出现 · · ·
│                               │
│ ┌───────────────────────────┐ │
│ │ 在此添加内容，按回车创建   │ │   ← 内置快速添加
│ └───────────────────────────┘ │
│                               │
│ ▾ 今天 周三                1  │   ← 组头可折叠
│ ▢ 报表                  今天  │
│                               │
│ ▾ 明天 周四                1  │
│ ▢ 背英语单词            明天  │
│                               │
│ ▾ 后天 周五                1  │
│ ▢ 123                   后天  │
└───────────────────────────────┘
```

- 默认尺寸 340 × 420，可自由调整
- 标题可切换范围：`最近待办 ▾`（今天 / 未来 3 天 / 未来 7 天）
- 组头：11px/500 `--w-text-sub`，可折叠（折叠态只留组头），右侧显示该组数量
- 任务行：高 30px，左侧 14px 方形勾选框（对应 2.jpg 的 `▢`），右侧相对日期标签 11px `--w-text-dim`
- 行悬停：`--w-row-hover`，并淡入完成/删除操作
- 组头与行内右侧日期标签**同时保留**：组件范围可切换，组头会变，行内标签更稳定；也与参考图一致
- 内置快速添加：Enter 创建，默认 `due_date = 明天`（可在 `▾` 里改默认落点），创建后清空并保持输入态

### 7.4 其余三种组件

沿用 v0.1 §5.2–5.4 的内容规格（今日待办 / 今日进度 / 快速添加），但**外观统一套用 7.2 深色玻璃 Token**，圆角统一 16px。

**必须支持（§十八，全部沿用既有架构）：** 无边框 / 半透明 / 置顶 / 拖动 / 调整大小 / 透明度 / 多组件 / 多显示器 / 位置记忆 / 重启恢复 / 悬停显示设置按钮 / 右键菜单。

### 7.5 数据共享（§十九，硬性要求）

主界面、看板、Widget 共用**同一个 SQLite + 同一个 `core/task` 业务层**。主进程写库成功后广播 `tasks:changed`，所有窗口（含 Widget）订阅刷新。**在任何一端完成任务，其他端立即更新**，不允许出现两套数据。

## 8. 全局快速添加窗（§十五）

保留，不属于看板，是全局功能。

- `Ctrl + Shift + Space` 呼出，320 × 56，居中、无边框、圆角 12、`--shadow-md`
- 占位符：`输入任务，回车创建`；下方 11px 灰字提示 `Esc 关闭 · Enter 创建`
- 呼出 80ms 缩放淡入（0.96→1），关闭瞬时无动画
- 创建语义：`due_date = 今天`（与看板「今日待完成」一致）；按 `Tab` 可切换落点为「待办池」（输入框下方出现两枚小标签：`今天` / `待办池`）
- **与 §3.4 捕获条共用同一套解析器**（`src/shared/capture-parse.ts`）：同样识别 `明天` / `周五` / `9-20` / `#标签`，解析结果同样显示在落点标签上，规则完全一致。区别只在窗口形态与默认落点，**不维护两套行为**
- 关闭时若有未提交内容，**保留草稿**（下次呼出仍在），避免误按 `Esc` 丢内容

## 11. 长文本与边界

| 场景 | 处理 |
| --- | --- |
| 卡片标题过长 | 卡片内最多 2 行，超出省略；编辑器内自动换行 |
| 「今天」页任务标题过长 | 单行省略 + `title` 属性全文 |
| 标签名过长 | 最多 4 字截断 |
| 窗口缩到最小（460 × 560） | 看板三列变横向滚动，每列固定 240px；侧栏折叠为 48px 图标条 |
| 大量任务（1000+） | 列内虚拟滚动；DB 侧 `LIMIT/OFFSET` |
| 中英混排 / emoji | 行高用倍数；emoji 单独 font-family 兜底 |
| 拖拽中窗口失焦 | 立即取消拖拽，卡片回弹 |
| **捕获条在窄窗口（460px）** | **chip 固定不压缩、永不换行；空间不足时优先截断占位符为 `记点什么…`；输入超过 24 字后占位符整体隐藏** |
| **捕获条输入极长（>200 字）** | 最多 3 行后内部垂直滚动；入库时标题截断为 200 字并在编辑器里提示 |
| **捕获条输入含 emoji / 中英混排** | 与表格其余处一致，行高用倍数，emoji 单独 font-family 兜底 |
